# Freedom AI

실시간 협업 무한 캔버스 툴 — 브라우저만 있으면 바로 시작, 링크 공유로 팀과 함께 그립니다.

## 주요 기능

| 기능 | 설명 |
|------|------|
| 무한 캔버스 | 마우스 휠·핀치 줌, 패닝으로 끝없이 펼쳐지는 작업 공간 |
| 펜 & 지우개 | 펜 3가지 굵기·5가지 색상 / 3가지 크기 소프트 브러시 지우개 |
| 포스트잇 | 5가지 색상, 이동·리사이즈·텍스트 편집, 글자 크기 4단계, 가장자리 핸들로 화살표 연결, 자석 스냅 |
| 도형 | 사각형, 원, 삼각형, 화살표(3가지 굵기) |
| 이미지 삽입 | Ctrl+V 붙여넣기 또는 드래그 & 드롭으로 이미지 추가·이동·리사이즈, 우클릭으로 앞뒤 순서 조절 |
| 배경 제거 | 이미지 위 가위 버튼 또는 꾹 누르기로 실행. 인물 사진은 AI로, 로고·텍스트 같은 그래픽은 명도 분석으로(흰/검은 배경 자동 판별) 처리, Ctrl+Z로 원본 복구 |
| 선택 툴 | 드래그로 여러 항목 범위 선택 후 한 번에 이동, Backspace/Delete로 일괄 삭제, 선택 박스 모서리로 한꺼번에 크기 조절(비율 유지) |
| 그룹 | 여러 항목을 선택해 그룹으로 묶으면 하나만 클릭해도 전체가 함께 선택·이동 (그룹 해제 가능) |
| 협업 To-Do | 툴바 캘린더에서 날짜를 골라 할 일 작성·체크·삭제, 팀원과 실시간 동기화 |
| 실시간 협업 | Pusher 기반 커서·획·포스트잇 실시간 동기화, 현재 접속자 표시 |
| 팀 초대 & 비공개 방 | 공유 버튼 → 초대 링크 복사(7일 유효), 비공개로 전환하면 초대된 멤버만 입장, 멤버 목록·내보내기 |
| Google 로그인 / 게스트 입장 | Google 계정으로 즉시 입장, 로그아웃 시 계정 초기화 / 로그인 없이 게스트로 체험 (게스트가 만든 방은 마지막 편집 24시간 후 자동 삭제) |
| 프로젝트 사이드바 | 좌측 사이드바에서 프로젝트 전환·추가·삭제 (`×` 버튼 + 확인 창), 우클릭으로 이름 변경 |
| 휴지통 | 삭제한 프로젝트 목록을 이 브라우저에 보관(최대 20개), 클릭으로 내용 열람, `×`로 목록·로컬 사본 삭제 (서버의 방 데이터는 남음) |
| 자유 이동 패널 | 상단 툴바·좌측 사이드바를 드래그로 자유롭게 이동 (PC), 위치 자동 저장 |
| 모바일 최적화 | 터치 드로잉·핀치 줌·이미지 터치 이동/리사이즈, 기종별 safe-area 대응 |
| 데이터 보존 | 방 상태는 서버(Vercel KV)에 저장, 브라우저(localStorage)에도 사본을 남겨 서버가 비어 있을 때 복원 |
| 한/영/일 전환 | UI 언어를 한국어·영어·일본어로 전환 (랜딩·앱 공통, 선택이 유지됨) |

> AI 이미지 변환(이미지 더블클릭 → 프롬프트로 스타일 변환)은 UI에 남아 있지만, Hugging Face 무료 프로바이더(hf-inference)가 GPU 이미지 생성을 더 이상 지원하지 않아 현재 동작하지 않습니다.

## 기술 스택

| 분류 | 기술 |
|------|------|
| 배포 | Vercel (Serverless Functions) |
| 실시간 | Pusher Channels (Presence Channel + Client Events) |
| 저장소 | Vercel KV (Redis) + localStorage 사본 |
| 인증 | Google Identity Services (GIS) OAuth 팝업 |
| 프론트엔드 | Vanilla JS, Canvas API |
| 백엔드 | Node.js Serverless (`/api/*.js`) |
| AI 이미지 처리 | Hugging Face, 별도 Express 서버(`hf-server/`, Render 배포) |

## 로컬 개발

### 1. 설치

```bash
npm install
```

### 2. 환경변수 설정

`.env` 파일 생성:

```env
PUSHER_APP_ID=your_app_id
PUSHER_KEY=your_key
PUSHER_SECRET=your_secret
PUSHER_CLUSTER=your_cluster

# 선택 — 없으면 방 상태가 서버에 저장되지 않고(브라우저 사본만 남음),
# 팀원 관리·방 이름 변경은 동작하지 않음
KV_REST_API_URL=your_kv_url
KV_REST_API_TOKEN=your_kv_token

# 선택 — /admin.html 통계·문의 조회 키 (없으면 그 페이지만 못 쓰고 캔버스는 정상 동작)
ADMIN_STATS_KEY=추측하기_어려운_긴_무작위_문자열

# 선택 — 본인 Google OAuth 클라이언트를 쓸 때만. 없으면 app.html에 하드코딩된 기본값을 쓴다.
# app.html의 GOOGLE_CLIENT_ID와 반드시 같아야 하며, 다르면 비공개 방 인증이 전부 실패한다.
GOOGLE_CLIENT_ID=your_client_id.apps.googleusercontent.com
```

### 3. 서버 실행

```bash
npx vercel dev  # /api/* 서버리스 함수까지 실행 (.env 사용)
```

`npm start` / `npm run dev`는 구버전 `server.js`(정적 파일 + WebSocket)만 띄우고
`/api/*`를 실행하지 않으므로, 페이지는 열리지만 방 입장·저장·실시간 동기화는 동작하지 않는다.

### 4. 테스트

```bash
npm test
```

`api/*.js`의 핵심 동작(획·노트·이미지·도형 삭제/이동, 지우개 결과, To-Do, 게스트 방
만료, 비공개 방 멤버 검증, 방 입장·조회, 프로젝트 이름 변경, 일괄 이동·그룹, 관리자
통계, 보안 회귀 — roomId 키 충돌·KV 실패·락·이름 변경 경합·소유권 백필·다른 앱 토큰 거부 등)을
실제 KV·Pusher 없이 인메모리 가짜 구현으로 검증한다 (`tests/`,
Node 내장 테스트 러너 사용, 별도 설치 불필요 — `@vercel/kv`·`pusher`는 `npm install`로
이미 받는 의존성을 그대로 재사용). 소유권 정책처럼 한 번 조용히 깨졌던 적 있는 동작은
회귀 테스트로 고정해뒀다.

## Vercel 배포

### 환경변수

| 변수명 | 필수 | 설명 |
|--------|------|------|
| `PUSHER_APP_ID` | ✅ | Pusher 앱 ID |
| `PUSHER_KEY` | ✅ | Pusher 키 |
| `PUSHER_SECRET` | ✅ | Pusher 시크릿 |
| `PUSHER_CLUSTER` | ✅ | Pusher 클러스터 (예: `ap3`) |
| `KV_REST_API_URL` | 선택 | Vercel KV URL (없으면 서버 저장·팀원 관리·이름 변경 불가) |
| `KV_REST_API_TOKEN` | 선택 | Vercel KV 토큰 |
| `ADMIN_STATS_KEY` | 선택 | `/admin.html` 통계·문의 조회 키 (없으면 그 페이지만 못 쓴다 — 캔버스는 정상) |
| `GOOGLE_CLIENT_ID` | 선택 | 본인 OAuth 클라이언트를 쓸 때만. `app.html`의 `GOOGLE_CLIENT_ID`와 같아야 한다 (쉼표로 여러 개 가능) |

### Pusher 설정

- Pusher 대시보드 **App Settings → Enable client events** 활성화 필수 (커서·그리는 중인 획 공유에 사용)

### Google OAuth 설정

Google 클라이언트 ID는 `app.html`의 `GOOGLE_CLIENT_ID`에 하드코딩돼 있고, 서버는 토큰이 이
클라이언트로 발급된 것인지 확인한다(`lib/auth.js`). 본인 OAuth 클라이언트를 쓰려면 `app.html`
값을 바꾸고 Vercel 환경변수 `GOOGLE_CLIENT_ID`에도 같은 값을 넣은 뒤, Google Cloud Console → 사용자 인증 정보 →
**Authorized JavaScript origins** 에 배포 URL 추가:

```
https://your-domain.vercel.app
```

### AI 서버 (배경 제거)

`hf-server/`를 Render에 배포하고(`render.yaml` 포함) 환경변수 `HF_TOKEN`(Hugging Face
토큰)을 설정한 뒤, `app.html`의 `HF_SERVER_BASE`를 배포 주소로 바꾼다. AI 서버는 허용된
출처(`ALLOWED_ORIGINS`, 기본값 `https://freedomai-app.vercel.app`과 localhost)에서 온 요청만
받고, IP당 분당 5회·서버 전체 분당 60회(`GLOBAL_RATE_LIMIT`)로 Hugging Face 호출을 제한한다.
다른 주소로 배포하면 `ALLOWED_ORIGINS`에 그 주소를 넣는다.

## 주요 정책

- 룸당 최대 획 1,000개 (획당 점 5,000개)
- 포스트잇: 룸당 최대 1,000개, 텍스트 최대 10,000자 / 너비 100~3,000px, 높이 80~3,000px / 글자 크기 10~32px
- 이미지: 룸당 최대 20개, 붙여넣기·드롭 시 최대 1,200px로 자동 압축 (JPEG 82%, 투명 배경은 흰색으로)
- 도형: 룸당 최대 300개
- To-Do: 날짜당 최대 50개, 항목당 200자
- 프로젝트 이름 최대 32자, 사이드바 프로젝트 목록 최대 30개
- 비공개 전환·프로젝트 이름 변경: 방 주인(로그인 사용자)만 가능. 주인은 방이 만들어질 때 기록되고, 게스트가 만든 방처럼 주인이 비어 있던 방은 로그인 사용자가 처음 작업하는 시점에 그 사람으로 기록된다 (그 이전에 만들어져 아직 아무 로그인 사용자도 쓰지 않은 방은 예전처럼 누구나)
- 지우개: 클라이언트에서 직접 계산 후 결과 전송 (KV 없이도 동작)
- 삭제·이동(포스트잇/이미지/도형/획): 방에 입장할 수 있는 사람이면 작성자 구분 없이 가능 (지우개와 동일 정책)
- 실행 취소(Ctrl+Z): 내가 이 탭에서 한 작업을 한 순서대로 최대 100단계 되돌린다 (삭제한 포스트잇·이미지·도형·획, 배경 제거, 일괄 삭제 포함). 다른 사람이 이미 바꿔놓은 항목은 건너뛴다
- 게스트가 만든 방: 마지막 편집 24시간 후 자동 삭제. 로그인 사용자가 그 방에서 한 번이라도 작업하면 만료가 해제된다
- 데이터: 방 상태는 Vercel KV에 저장, 브라우저 localStorage에도 사본 저장 (서버가 비어 있을 때 복원)
- 패널 위치(툴바·사이드바): PC에서 드래그 이동, localStorage에 저장

- **오픈 방 권한** — 방 이름만 알면 누구나 그 방을 비공개로 잠그거나(함께 쓰던 사람 차단) 이름을 바꿔 옮길 수 있었음. 로그인한 사용자가 방을 처음 만들면 만든 사람으로 기록하고, 비공개 전환·이름 변경은 그 사람만 할 수 있게 함. 만든 사람 이메일은 다른 사용자에게 내려보내지 않음

- **실행 취소를 시간 순서대로** — "마지막 삭제 1건 / 마지막 이미지 편집 1건 / 내 획"이 따로 저장되고 고정 우선순위로 꺼내져서, 노트를 지운 뒤 획을 그리고 Ctrl+Z를 누르면 노트가 먼저 돌아오는 식으로 순서가 뒤섞였음. 한 일을 순서대로 쌓아 최근 것부터 되돌리고(최대 100단계), 여러 개를 한꺼번에 지운 건 한 번에 복원. 선택 툴로 지운 펜 획도 되돌릴 수 있고, 되살린 항목이 글자 크기·그룹·앞뒤 순서·배경 제거 상태를 잃지 않음

- **게스트 방을 이어 쓰면 하루 뒤 사라지던 문제** — 게스트 표시가 한 번 붙으면 떨어지지 않아, 로그인 사용자가 그 방을 계속 써도 쓰기마다 24시간 만료가 새로 걸렸음(게스트로 체험 → 로그인해서 계속 쓰는 흔한 흐름에서 하루만 쉬면 작업 전체 삭제). 로그인 사용자가 작업하면 만료를 해제함
- **이름 변경이 방을 통째로 날리던 문제** — 이름 변경이 "읽어서 비었는지 확인 → 쓰기"였고 방 락도 잡지 않았음. 서로 다른 두 방을 같은 이름으로 동시에 바꾸면 둘 다 성공으로 응답하고 한쪽 방이 오류 없이 사라졌고, 변경 중에 들어온 그리기는 이미 지워진 옛 이름에 되살아나 방이 두 이름으로 갈라졌음. 이름 선점을 원자적으로 바꾸고 캔버스 저장과 같은 락을 쓰게 함
- **입력 중 페이지를 떠나면 마지막 글자가 사라지던 문제** — 포스트잇 입력은 0.4초, 로컬 사본은 0.6초 묶어서 저장하는데 떠나는 시점에 확정하는 코드가 전혀 없었음. 사이드바에서 다른 프로젝트를 누르면 즉시 새로고침이 돌아 서버·브라우저 양쪽에서 유실됐음. 탭을 닫거나 백그라운드로 보낼 때도 확정하고, 떠나는 중에도 취소되지 않는 방식으로 전송함
- **방 입장이 실패를 숨기고 백지를 주던 문제** — 서버 읽기가 실패하면 "저장소 미설정"과 같이 묶어 삼키고 빈 캔버스를 정상 응답으로 돌려줬음. 처음 들어오는 팀원은 오류 한 줄 없이 백지를 받아 그게 방의 전부라고 믿게 됐음. 이제 오류로 알려 다시 시도하게 함
- **프로젝트 목록도 같은 경로** — 목록 읽기 실패 시 빈 목록을 정상 응답으로 돌려줘서, 사이드바가 비어 보이고 거기서 하나라도 추가하면 그 한 개가 원래 목록을 덮어쓸 수 있었음. 이메일 대소문자에 따라 다른 칸을 읽고 쓰던 문제도 함께 고침
- **모바일에서 엉뚱한 좌표가 저장되던 문제** — 드래그 중 알림을 끌어내리는 등 시스템 제스처가 끼면 브라우저가 touchend 대신 touchcancel을 보내는데 이걸 듣지 않아 리스너가 영구히 남았음. 이후 화면 어디를 터치해도 선택 항목이 순간이동하고, 손을 뗄 때마다 그 좌표가 방 전체에 저장됐음
- **브라우저 사본에서 이미지 앞뒤 순서·배경 제거가 사라지던 문제** — 로컬 사본에 순서(z)와 배경 제거 여부를 저장하지 않아, 서버가 비어 이 사본으로 복원되면 순서가 전부 뭉개지고 잘라낸 이미지에 사각 테두리가 돌아왔음
- **팀원이 바꾼 할 일이 브라우저 사본에 빠지던 문제** — 원격 할 일 추가·체크·삭제만 로컬 저장을 호출하지 않았음

동작 오류
- **포스트잇 삭제 ×가 터치에서 안 먹던 문제** — 선택 툴에서 ×를 누르면 삭제 대신 드래그가 시작돼, 삭제는 안 되고 노트가 1px 밀린 것만 팀원에게 전송됐음(마우스에는 있던 예외 처리가 터치 경로에만 빠져 있었음)
- **이미지·도형 한도 초과를 조용히 버리던 문제** — 이미지 20장·도형 300개를 넘기면 서버가 저장하지 않고 성공으로 응답해서, 화면에는 그려진 채 남았다가 새로고침하면 그 항목만 사라졌음. 사유를 돌려주고 화면에서도 되돌린 뒤 이유를 알려줌
- **노트를 지우면 화살표 연결이 새로고침 전후로 달라지던 문제** — 연결을 로컬에서만 풀고 서버에는 알리지 않아, 새로고침하면 화살표가 사라진 노트 자리로 다시 붙어 두 사람 화면이 어긋났음. 서버에도 반영하고, 되돌리기로 노트를 살리면 연결까지 복원함
- **로그인 연장 버튼이 안 눌리던 경우** — Google 스크립트가 차단된 상태면 아무 반응이 없었고, 브라우저에 Google 세션이 없거나 다른 계정이면 같은 버튼만 반복해 눌러도 벗어날 수 없었음(새로고침밖에 답이 없었음). 이유를 알려주고, 한 번 실패하면 계정 선택 창으로 올라감
- **AI 프롬프트 입력창에 이미지를 붙여넣으면 캔버스로 가던 문제** — 붙여넣기 처리가 `textarea`를 예외로 두지 않았음 (키보드 단축키 쪽은 이미 처리돼 있었음)
- **되돌리기가 사진 원본을 계속 붙잡던 문제** — 되돌리기를 100단계로 늘리면서 배경 제거·삭제한 사진의 원본(장당 최대 1.9MB)이 전부 메모리에 남아, 모바일에서는 탭이 죽고 아직 전송 안 된 변경까지 같이 날아갈 수 있었음. 이미지 용량 예산을 두고 오래된 것부터 버림
