KPT振り返り：プロジェクト後30分でできる整理法

2026-11-14 · 5分で読めます

プロジェクトが終わると、みんな疲れてすぐ次の仕事に移ります。そして次のプロジェクトで同じ失敗を繰り返します。振り返りは大げさなものである必要はありません。3つのエリアと30分があれば十分です。

KPTとは

  • Keep — うまくいったこと、次も続けること
  • Problem — 残念だったこと、自分たちを遅くしたもの
  • Try — 次に新しく試すこと

シンプルですが、順番に意味があります。うまくいったことから話すと場がほぐれ、問題を出すときに身構えることが減ります。

キャンバスの準備（2分）

四角形を3つ横に並べて描き、それぞれ Keep、Problem、Try と書きます。エリアごとに付箋の色を決めておくと便利です。Keep は緑、Problem はピンク、Try は黄色のように。エリアの上に「今回のプロジェクト：○○リニューアル（9月〜11月）」のように範囲を書いておくと、話が脇道にそれません。

Keep を書く（5分）

それぞれ黙って Keep エリアに付箋を貼ります。「毎朝10分の共有がよかった」のように具体的なほど良いです。書き終えたら一人ずつ短く読み上げ、似たものは重ねて貼ります。

Problem を書く（8分）

いちばん気をつけるべき段階です。ルールは1つ、人ではなく状況を書く。「○○さんの受け渡しが遅かった」ではなく、「デザインレビューの日程が開発の日程と重なった」と書きます。問題を人から切り離してはじめて、解決策を話し合えます。

Problem がたくさん出たら似たものをまとめ、ドット投票でいちばん痛かった問題を2、3個選びます。

口に出しにくい問題も、付箋になら書きやすいものです。黙って書く時間を十分にとりましょう。

Try を決める（10分）

投票で選んだ Problem ごとに Try を1つずつ貼ります。Try は来週すぐ試せるくらい小さくなければなりません。「コミュニケーションをよくしよう」は Try ではなく決意表明です。「デザインレビューは毎週火曜の午後に固定する」が Try です。

まとめ（5分）

決めた Try はカレンダーのToDoに移して担当者をつけます。そして次の振り返りの日程を先に決めておきましょう。次の振り返りは、前回の Try が実際に効果があったかを確認するところから始めます。こうして続けることで、振り返りは一度きりのイベントではなく、チームが少しずつ良くなっていく仕組みになります。

ボードはPNGで保存してプロジェクトの資料に添付しておくと、半年後に似たプロジェクトを始めるときの良い参考資料になります。
